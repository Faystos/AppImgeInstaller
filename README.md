# add-appimage.sh

Bash-скрипт для управления AppImage-приложениями в пользовательском окружении Linux — установка, обновление, ремонт иконок, удаление и просмотр списка установленных приложений. Не требует root-прав: все файлы размещаются в `~/.local`.

## Что делает скрипт

При установке AppImage-файла скрипт автоматически выполняет три шага:

1. **Копирует бинарник** в `~/.local/bin` (атомарно: временный файл + `mv`, оригинал сохраняется) и выставляет бит исполнения.
2. **Извлекает иконку и метаданные** из самого AppImage (через `--appimage-extract`): встроенный `.desktop`-файл, `.DirIcon` или лучшую иконку по имени/размеру. Иконка копируется в `~/.local/share/icons` с определением реального формата по MIME-типу (png/svg/jpg/ico). Если автоматически иконку найти не удалось и есть графическая сессия с `zenity` — предлагается выбрать файл иконки вручную.
3. **Создаёт `.desktop`-ярлык** в `~/.local/share/applications` с полями `Name`, `Comment`, `Exec`, `Icon`, `Categories`, `Keywords`. Ярлык пишется атомарно, с бэкапом `.bak` и валидацией через `desktop-file-validate` (если доступен). Каждый ярлык помечается маркером `X-AppImage-Installer=true`, по которому скрипт отличает «свои» ярлыки от чужих.

В результате приложение появляется в меню приложений (GNOME/KDE/XFCE и т.д.) и в `PATH` (если `~/.local/bin` в `PATH`).

## Требования

- **bash >= 4** (используются ассоциативные массивы и `${var,,}`).
- **AppImage type 2** — формат проверяется по magic bytes (ELF-заголовок + сигнатура `AI\x02`). Файлы type 1 и не-AppImage отклоняются с диагностикой.
- Опционально: `file` (определение формата иконки), `desktop-file-validate` (валидация ярлыка), `update-desktop-database` (обновление кэша меню), `zenity` (GUI-выбор иконки), `readlink`, `stat`, `md5sum`.

## Режимы работы

| Режим | Команда | Описание |
|---|---|---|
| Установка | `./add-appimage.sh [ОПЦИИ] файл.AppImage` | Копирование + ярлык + иконка |
| Ремонт иконки | `./add-appimage.sh --fix-icon [--icon PATH] <имя>` | Повторное извлечение или ручная замена иконки |
| Удаление | `./add-appimage.sh --remove [-y] <имя>` | Удаление бинарника, ярлыка и иконки |
| Обновление | `./add-appimage.sh --update <имя> <новый.AppImage>` | Замена бинарника с сохранением ярлыка |
| Список | `./add-appimage.sh --list` | Список установленных AppImage-приложений |

Режимы взаимоисключающие. Опции, неприменимые в выбранном режиме, отклоняются с ошибкой, а не игнорируются молча.

## Опции

| Опция | Назначение |
|---|---|
| `--name NAME` | Отображаемое имя приложения в меню |
| `--icon PATH` | Путь к иконке (png/svg/jpg/jpeg/ico); имеет приоритет над автоизвлечением |
| `--categories LIST` | Категории ярлыка: `"Development;IDE;"` или `"Development,IDE"` |
| `--comment TEXT` | Описание приложения (поле `Comment=`) |
| `--keywords LIST` | Ключевые слова для поиска в меню |
| `--exec-args ARGS` | Аргументы командной строки в `Exec=` (напр. `--no-sandbox`); при `--update` заменяют старые |
| `-y, --yes` | Не спрашивать подтверждение (только для `--remove`) |
| `-h, --help` | Справка |

Для всех опций поддерживается формат `--opt=значение`; он **обязателен**, если значение начинается с `-` (например: `--exec-args="--no-sandbox"`).

## Примеры использования

```bash
# Простая установка
./add-appimage.sh ~/Downloads/Cursor.AppImage

# Установка с пользовательским именем, категориями и иконкой
./add-appimage.sh --name "Мой Редактор" \
    --categories "Utility;TextEditor;" \
    --icon ~/icons/editor.png \
    app.AppImage

# Установка с аргументами запуска (напр. для Electron-приложений)
./add-appimage.sh --exec-args="--no-sandbox" app.AppImage

# Ремонт иконки (автоматически из бинарника)
./add-appimage.sh --fix-icon cursor

# Ремонт иконки (указать файл вручную)
./add-appimage.sh --fix-icon --icon ~/icon.png cursor

# Обновление бинарника (ярлык, иконка и аргументы Exec= сохраняются)
./add-appimage.sh --update cursor ~/Downloads/Cursor-2.0.AppImage

# Удаление (с подтверждением / без подтверждения)
./add-appimage.sh --remove cursor
./add-appimage.sh --remove -y cursor

# Список установленных
./add-appimage.sh --list
```

В режимах `--fix-icon`, `--remove`, `--update` приложение можно указывать подстрокой имени файла (без учёта регистра) или точным путём к `.AppImage`. Если подстрока совпадает с несколькими файлами — скрипт откажет и перечислит совпадения.

## Структура размещения файлов

```
~/.local/bin/<имя>.AppImage                  — бинарник
~/.local/share/applications/<имя>.desktop    — ярлык (+ .bak бэкап)
~/.local/share/icons/<имя>.<png|svg|jpg|ico> — иконка
```

Имя нормализуется: латиница приводится к нижнему регистру, кириллица транслитерируется, остальные символы заменяются на `-` (например, `My App.AppImage` → `my-app.desktop`).

## Приоритеты метаданных при установке/переустановке

- **Name**: `--name` → имя из старого ярлыка → встроенное в AppImage → капитализация имени файла.
- **Comment**: `--comment` → встроенный → старый из ярлыка.
- **Categories**: `--categories` → встроенные → старые → `Utility;`.
- **Keywords**: `--keywords` → встроенные → старые.
- **Иконка**: `--icon` → текущая иконка ярлыка (при переустановке) → извлечение из AppImage (`.DirIcon` → поиск по имени из `Icon=` → самая большая png/svg, при необходимости после полной распаковки) → диалог `zenity` → дефолт `application-x-executable`.

При повторной установке без опций скрипт сообщает, что приложение уже добавлено, и подсказывает команды `--fix-icon` / `--update`.

## Особенности и безопасность

- **Атомарность**: копирование бинарников и запись/изменение ярлыков выполняются через временный файл на той же файловой системе + `mv`; при ошибке или прерывании целевой файл не повреждается, а временные файлы удаляются обработчиком `trap` (включая корректную обработку `Ctrl+C`/`SIGTERM` с сохранением кодов выхода 130/143).
- **Бэкапы**: перед перезаписью ярлыка создаётся `<имя>.desktop.bak`; при сбое обновления `Exec=`/`Icon=` ярлык откатывается из бэкапа.
- **Защита чужих ярлыков**: ярлык, найденный только по похожему имени или не созданный этим скриптом (без маркера `X-AppImage-Installer`), не удаляется и не переписывается без явного подтверждения.
- **Защита файлов вне `~/.local/bin`**: удаление/обновление AppImage, заданного точным путём вне целевого каталога, требует интерактивного подтверждения (флаг `-y` не помогает).
- **Неинтерактивный запуск** (cron/CI): без терминала подтверждения трактуются как отказ — скрипт не зависает и не соглашается молча.
- **Валидация входных данных**: запрет переводов строк в метаданных, запрет кавычек в имени файла, экранирование кавычек/бэкслешей в `Exec=` по спецификации desktop-entry, корректная обработка glob-символов в путях.
- **Сравнение файлов по device:inode** (а не по строкам путей) — корректно работает при симлинках; запуск от root вызывает предупреждение, так как файлы попадут в `/root/.local`.
- **Удаление дубликатов иконок**: при смене формата иконки старые файлы с тем же базовым именем удаляются.
- **Удаление дубликатов ярлыков**: при установке под новым именем (`--name`) предлагается удалить старый ярлык, ссылающийся на тот же бинарник.

## Замечания по режиму --update

- Новый бинарник всегда занимает путь, на который уже ссылается ярлык, — версионные имена файлов не плодятся.
- Аргументы `Exec=` сохраняются со старого ярлыка, если не задан `--exec-args`.
- Старый бинарник (если ярлык ссылался на другой файл) удаляется автоматически только внутри `~/.local/bin` при достоверном совпадении; в остальных случаях — с подтверждением.
- Иконка при обновлении не меняется; для её обновления из нового бинарника используйте `--fix-icon`.

## Выход из скрипта

Код выхода `0` — успех (или осознанная отмена пользователем), `1` — ошибка. При прерывании сигналом: 130 (`SIGINT`), 143 (`SIGTERM`).
